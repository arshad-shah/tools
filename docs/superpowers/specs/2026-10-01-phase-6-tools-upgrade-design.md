## 1. Intent

Every non-PDF tool becomes the best free, private version of itself: correct, fast on large input, keyboard-driven, shareable where that is safe, and connected to its neighbours. All of it composes from the phase-5 kit and follows the §1A design-system rules with zero violations.

**Success criteria**

1. All 22 existing non-PDF tools implement every upgrade listed for them in §8; all 10 new tools in §9 ship. That makes 32 non-PDF tools (this corrects phase-5 §1 criterion 6, which said 30).
2. No tool blocks the main thread for more than 100 ms on its documented "large input" fixture (§12.4). Regex and other user-supplied patterns can never freeze the tab: they time out with `TIMEOUT`.
3. The JSON & XML Viewer opens a 20 MB JSON document. Its Tree view scrolls at 50 fps or better, and its Map view pans and zooms at 50 fps or better with 5,000 cards on screen budget (culling and level of detail). Layout runs in a worker. `@xyflow/react` and `dagre` are gone.
4. Every text-input tool uses `TextInputPanel` (§4.1). Every tool whose output another tool can take offers **Send to** (§4.3). Every tool on the share allow-list (§4.2) has a working Share link, and no tool outside it does.
5. Plotly, React Flow, dagre, `@uiw/react-textarea-code-editor`, `rehype-*`, `crypto-js` and `lodash` are removed from `package.json`. Bundle budgets in §12.5 hold.
6. Lint (all `local/*` rules at `error`), typecheck, unit, component, e2e (three green runs) and build pass. The visual suite passes in both themes, with axe reporting 0 serious or critical issues on every tool page.
7. Nothing is faked. Every failure surfaces as a `ToolError` with a user-facing message, and every fallback is reported in the UI.

## 3. Inherited rules and new global behaviours

All phase-5 §1A rules apply unchanged:

- **R1:** icons only from `@/shared/ui/icons`.
- **R2:** no hand-rolled UI. A missing capability means a kit component is added first (§5), with tests and a `/__kit` gallery entry.
- **R3:** no emoji, pictographic, arrow, bullet or box-drawing glyph in any product string, test name in `src`, fixture meant for display, or built asset. Product copy says "to", "and" and so on.
- **R4:** CI enforcement.

The `ToolError` model applies, and so does client-side only. Behaviours that every tool gets in phase 6:

| Behaviour    | Rule                                                                                                                                                                                                                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Live results | No "Run" buttons for pure transforms. Input is debounced (150 ms text, 0 ms toggles), and work over 16 ms moves to a worker (§4.4). Buttons remain only for actions with side effects (download, send request, start timer).                                                                                                                                     |
| Errors       | Parse and validation errors show inline next to the input, with line:column where the input is code-like. They never leave stale results visible: results clear or dim with an "Out of date" state.                                                                                                                                                              |
| Persistence  | **Settings are persisted, data never is.** Every tool's options use `createToolSettings` (§4.5). Documents, inputs, outputs, tokens, keys and passwords are never written to storage. The exceptions are explicit opt-ins named in §8 (HTTP Client secret values, HTTP history), always labelled and clearable.                                                  |
| Keyboard     | Each tool registers commands through `useToolCommands` (§4.6). Common keys: Mod+Enter run or send, Mod+Shift+C copy primary output, Mod+Shift+S share (where allowed), Mod+O open file, Mod+Shift+X clear, `?` shortcut sheet. Single-key shortcuts are disabled while typing.                                                                                   |
| Network      | None, except: **HTTP Client** (sends what the user asks; banner "Requests go directly from your browser to the URL you enter"), and **Markdown and HTTP HTML previews**, which block remote resources by CSP until the user opts in per document ("Load remote images", labelled). Every other tool is covered by request-log e2e assertions (same-origin only). |
| Privacy note | Tools that handle secrets (JWT, Hash HMAC, Password, Encrypt, HTTP Client) show the kit `PrivacyNote` ("Nothing leaves your browser" or the network wording above).                                                                                                                                                                                              |
| Large input  | `TextInputPanel` warns above 5 MB ("Large input: processing in the background") and refuses above each tool's hard cap with `TOO_LARGE`, naming the cap.                                                                                                                                                                                                         |

### 4.2 Share via URL (`src/shared/lib/share-state.ts`)

- **Format:** `#s=1.<payload>`, where `payload = base64url(deflateRaw(utf8(JSON.stringify(state))))` (fflate). Hash only, so it is never sent to a server.
- **Limits:** serialised JSON at most 64 KB before compression, and the encoded fragment at most **6,000 characters**. Over either limit, the Share button is disabled with the tooltip "Too large to share as a link (n KB)". Decoding refuses fragments over 16,000 characters and decompressed JSON over 256 KB (zip-bomb guard), and reports `INVALID_INPUT` "This share link is damaged or from a newer version".
- **Schema:** every sharing tool supplies `parse(unknown): State | null` (hand-written validator, no new dependency) and a `version`. Unknown versions are refused with a message, never partially applied.
- **Hook:** `useShareableState<S>({ toolId, version, parse, select })` returns `{ share(): Promise<string>, canShare, reason?, loaded: S | null }`.
  - `share()` builds the URL and copies it.
  - On mount the tool hydrates once from `loaded`, shows a dismissible `Alert` "Loaded from a shared link", and removes the fragment with `history.replaceState`. Later edits never rewrite the URL.
- **Allow-list (only these tools call the hook):**

| Tool                    | Shared state                                             | Notes                                                                                                                         |
| ----------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Regex Tester            | pattern, flags, test text, replacement, mode, test cases |                                                                                                                               |
| Text Diff               | left, right, options                                     | size cap applies (usually small diffs only)                                                                                   |
| Calculator              | expression sheet, angle, precision                       |                                                                                                                               |
| Number Base Converter   | value, width, signedness                                 |                                                                                                                               |
| Unit Converter          | category, value, unit                                    |                                                                                                                               |
| Date & Time Calculator  | mode, inputs, zone, workweek, holidays                   |                                                                                                                               |
| Epoch & Time Zone       | instant, zones list                                      |                                                                                                                               |
| Cron Builder            | expression, flavour, zone                                |                                                                                                                               |
| Color & Contrast        | colours, palette, scale settings                         |                                                                                                                               |
| QR Code Generator       | type, fields, style                                      | **not** for WiFi or any type with a password field (the button hides)                                                         |
| Mock Data Generator     | schema, seed, count, locale                              | the schema, never the generated data                                                                                          |
| URL Inspector & Builder | the URL                                                  | userinfo password stripped; a warning if query keys look secret (`token`, `key`, `sig`, `password`, `secret`, `auth`, `code`) |

**Never shared:** Password, JWT, Hash (input and key), HTTP Client, Encrypt, Base64, Text Encoder, Text Toolkit, Log Viewer, CSV and JSON data, Markdown, Code Formatter, EXIF, image tools, Favicon, QR Scanner, UUID, Pomodoro. A unit test asserts the set of tools that import `useShareableState` equals this allow-list.

### 4.3 Hand-off bus (`src/shared/lib/handoff.ts`, extends P5)

```ts
export type HandoffPayload =
  | { kind: 'files'; files: File[]; sourceTool?: string }
  | {
      kind: 'text';
      mime: string;            // e.g. 'application/json', 'text/csv', 'application/jwt'
      text: string;
      sourceTool: string;      // tool id
      filename?: string;
      meta?: Record<string, string | number | boolean>; // e.g. { side: 'left' } for Text Diff
    };

putHandoff(p: HandoffPayload): string;                  // one-time id; in memory only
takeHandoff(id: string): HandoffPayload | null;         // consumes the entry
useHandoff(match: (p: HandoffPayload) => boolean): HandoffPayload | null; // reads ?handoff= once, strips the param (replace)
sendTo(navigate, toolId: string, p: HandoffPayload): void; // put + navigate to the tool route
```

- **Lifecycle:** entries live at most 5 minutes and at most 8 entries (LRU). Text payloads are capped at 50 MB (`TOO_LARGE`). Nothing is persisted. A refresh loses the hand-off, and the target then shows its normal empty state, which is not an error.
- **Discovery:** manifest `accepts` gains `mimes?: string[]` (text) alongside P5's `kinds` (files). `SendToMenu` (§5) lists enabled tools whose `accepts.mimes` match the payload mime, excluding the source tool, with the icon and name from the registry. Registry validation rejects malformed mimes.
- **Secrets:** a payload may carry a secret (Password to PDF Protect, to Encrypt). Only the id is in the URL. Payloads are never logged.

### 4.5 Persisted settings: `createToolSettings`

`createToolSettings<S>(toolId, defaults, { version, migrate? })` is a thin wrapper over `createToolStore`.

- The store key is unchanged (`kit:store:tool:<id>`), so existing stores (calculator, api-request, pomodoro) keep their data through `migrate`.
- It returns a hook `[settings, update, reset]`.
- Values must be JSON. A unit test per tool asserts the settings shape contains no fields from a deny-list: `input`, `text`, `token`, `secret`, `password`, `key`, `body`, `data` (a data-never-persisted guard).

### 4.6 Tool commands and shortcuts

`useToolCommands(toolId, commands)` registers with P5's `useCommands`.

- A command is `{ id, label, shortcut?, run, enabled? }`.
- Shortcuts go through `shared/lib/hotkeys.ts` with the editable-target guard.
- The shortcut sheet (`?`) lists the tool's commands.
- Every tool registers at least: Copy result, Clear, Load sample (if any), plus the tool-specific ones named in §8 and §9.

### 6.3 Pipeline

`buildCards(nodes, theme, measure)`, then `layout(cards, edges, opts)`, then `route(cards, edges)`, then `SpatialIndex.build(cards, routes)`, then `paint(ctx, input)`, with `toSvg` and `toPng` as alternate outputs. The data stays plain arrays and objects so it can be structured-cloned.

### 6.4 Worker layout

- `layout.worker.ts` exposes `layoutDiagram(nodes, edges, opts, metrics)` through `worker-rpc`. It returns card positions and sizes as `Float64Array` (transferred) plus routes as a packed `Float64Array` with an offsets table.
- It is used when the node count is over 300 or the row count is over 5,000; smaller diagrams lay out synchronously.
- Results are deterministic: a test asserts identical geometry from the worker path and the main-thread path.

### 6.5 Performance budgets

- Layout of 5,000 cards / 40,000 rows in at most 800 ms in the worker (CI perf test, not PR-blocking at first).
- Paint at most 8 ms per frame for any viewport (culling plus LOD).
- Memory: no per-row objects on the main thread beyond the model.
- **Node cap:** the adapter emits at most 2,000 cards by default. Deeper subtrees become a `more` row ("+340 more"), and clicking it expands that subtree (re-layout). A Map toolbar control shows "Showing 2,000 of 12,431 objects".

### 6.6 Theme

The palette is snapshotted from live tokens and refreshed on `data-theme` change, so there are no colour literals. `prefers-reduced-motion` disables animated recentring (an instant jump instead).

## 16. Out of scope

- Server-side anything: proxies (HTTP Client CORS cannot be bypassed), currency rates, holiday APIs, link previews.
- Bundled public-holiday datasets (D6), GIF recording (D10), HEIC/AVIF/TIFF metadata removal (re-encode instead), shoe and clothing sizes, Subnet/CIDR calculator, SVG optimiser, Lorem ipsum as its own tool (Mock data covers lorem fields), jq (JSONPath only).
- Collaborative or cloud features; persisted documents (Markdown drafts, HTTP response bodies).
- Images to PDF upgrades beyond accepting the image hand-off.
- Regex flavours other than JavaScript for execution (export snippets only, with warnings).
- PDF workspace work (phase 5 Parts B–H).
