## Strengths

- **Crypto envelope is sound where it matters.**
  - Every `seal` uses a fresh 16-byte salt and a fresh 12-byte IV, so the key is new each time and GCM nonce reuse cannot happen.
  - The whole header is the GCM AAD.
  - The passphrase is NFC-normalised.
  - The magic, version and KDF id map to the spec's error codes (`INVALID_INPUT`, `UNSUPPORTED_FEATURE`, `WRONG_PASSWORD`).
  - The KDF parameters are range-checked before derivation.
  - There is no `Math.random` anywhere in the diff.
  - `randomInt` uses correct rejection sampling. The `0xFFFFFFFF` rejection test proves it.
  - `randomBytes` chunks at the 64 KB `getRandomValues` limit.
- **@noble/hashes per R29**, with a clean `DIGESTS` table and correct `broken` and `nonCrypto` flags. I checked the hand-written XXH64 and XXH3-64 against `xxhash.h`, branch by branch: 0, 1-3, 4-8, 9-16, 17-128 and 129-240 bytes, plus the long path with the last-stripe and scramble timing. They match, and streaming is correct across chunk borders. CRC-32 and CRC-32C use the right reflected polynomials. RFC 4231 HMAC is covered.
- **Share codec** never trusts input:
  - prefix and version checks
  - the 16,000-character cap is applied before Base64 decoding
  - strict Base64url
  - fatal UTF-8 decoding
  - an envelope shape check
  - every failure maps to the single spec message
  - newer versions are refused in the hook before `parse`
- **json-locate** is truly iterative. It handles `__proto__` as an own property, has precise error positions and duplicate warnings, and does a binary search in `nodeAtOffset`. `xmlToJson` also uses `defineProperty`, so it is safe against prototype pollution.
- **createToolSettings** goes through store-kit's `deserialize` so `migrate(old, fromVersion)` gets the stored version. It refuses newer versions, sanitises unknown or mistyped keys, and falls back to defaults when a migration throws, which store-kit catches.
- **Handoff** keeps the P5 `File[]` callers and the StrictMode-safe peek-then-take. A payload that `match` rejects stays for the other Diff panel. Mime validation and `toolsAccepting` filter out disabled tools.
- **Colour engine constants are right**: the APCA 0.0.98G-4g constants, all three Machado 2009 severity-1.0 matrices, and WCAG compositing.
- **Tokenisers** survived a 3,900-input random fuzz across all 14 languages with no hang, no throw and no empty or negative token.
- **Token block and test**: the contrast test now reads appended blocks and adds a deuteranopia deltaE check for adjacent chart colours. Dark and light both use the same `data-theme` selectors as the base block.
- **Coordination is clean**: no `src/pdf/**`, no workspace files, and no network calls (no `fetch`, XHR or WebSocket in the diff).

## Issues

### Critical

None.

### Important

**I1. A crafted `.enc` file can freeze or crash the tab: the Argon2id bound does not work.** `src/shared/lib/crypto/aead.ts:41-44`, `:70-80`, `:179`

- **Why:** `LIMITS` allows `memoryKiB` up to 1 GiB and `iterations` up to 255, and `open()` derives the key before it can authenticate anything.
  - I measured noble's pure-JS Argon2id at about 6.6 ms per MiB per pass (64 MiB, t=1 took 431 ms in Node). A header with m = 1 GiB and t = 255 means roughly 29 minutes of work and a 1 GiB allocation, which crashes mobile tabs.
  - The comment says "Bounds a crafted file cannot push a decrypt past (memory and time)", but the bound only defeats `0xFFFFFFFF`.
  - Decrypting a received file is the main Encrypt flow, so the input is attacker-controlled.
- **Fix:**
  - Cap decrypt-side Argon2id at about `memoryKiB <= 262_144` (256 MiB) and `iterations <= 10`, plus a total-cost cap such as `memoryKiB * iterations <= 1_048_576` (about 7 s).
  - Keep PBKDF2 at 10M or lower it to about 5M.
  - Add a test that a header with m = 1 GiB and t = 255 is refused with `INVALID_INPUT` before any derivation.
  - Optionally let `open` take an `AbortSignal` so the E-part UI can cancel.
  - The spec wants Argon2id in a worker; record that in the E handoff note.

**I2. `parseInstant('now ± …')` is an hour off during the repeated autumn hour.** `src/shared/lib/time/parse.ts:176-219`

- **Why:** for the `now` base, the code turns `now` into wall-clock fields and back through `wallClockToEpoch`, which resolves an ambiguous time to the earlier instant.
  - In the second 01:xx hour after fall-back, every relative result is shifted by one hour.
  - Probe in America/New_York with now = 2024-11-03T06:30Z (01:30 EST): `now - 2h` lands 3 h before now, and `now + 0h` lands 1 h before now.
  - Epoch and Date tools that offer "now - 2h" give a silently wrong answer.
- **Fix:**
  - When `base === 'now'` and there are no calendar units, return `now + exactMs`.
  - When calendar units are present, keep the original offset when it is still valid for the shifted wall clock (Temporal "compatible" behaviour from the instant). At minimum, pick the candidate whose offset equals the starting offset.
  - Add a test at 2024-11-03T06:30Z in New York.

**I3. SQL export splits dotted column names into qualified identifiers.** `src/shared/lib/data-formats/sql-insert.ts:15-24` and `:52-54`

- **Why:** `quoteIdent` splits on `.` for every identifier, including column names.
  - Probe: `toSqlInsert([{ 'a.b': 1 }], …)` gives `INSERT INTO "t" ("a"."b") VALUES (1);`, which is invalid SQL.
  - `flattenObject` in the same module family produces exactly these `a.b` keys, so the JSON to CSV/SQL and Mock data to SQL paths break on any nested data.
- **Fix:**
  - Split on dots only for the table name, through a `quoteTableName`.
  - Quote columns whole with `quoteIdent(name, dialect, { qualified: false })`.
  - Add a test with a dotted column for each of the four dialects.

**I4. `jsonToXml` rejects `xmlns`, `xml:lang` and `xml:space`, so XML to JSON to XML fails for namespaced documents.** `src/shared/lib/data-formats/xml.ts:200-208`

- **Why:** `checkName` throws on any name that matches `/^xml/i`.
  - Names that start with `xml` are reserved, but they are well-formed. `xmlns`, `xmlns:*` and `xml:*` are required by real documents: SOAP, SVG, Maven POMs, Atom and XHTML.
  - Probe: `xmlToJson(<r xmlns="urn:x" xml:lang="en">…)` gives `{"r":{"@xmlns":…,"@xml:lang":…}}`, and `jsonToXml` then throws `"xmlns" is not a valid XML element or attribute name`.
  - The plan requires "jsonToXml inverts it", and the 6-B JSON/XML viewer conversion depends on this.
- **Fix:**
  - Drop the `/^xml/i` rejection, or allow `xmlns`, `xmlns:<ncname>` and `xml:<ncname>` explicitly.
  - Add a round-trip test with a default namespace, a prefixed namespace and `xml:lang`.

### Minor (for `.superpowers/sdd/minors-backlog.md`)

**Share codec and handoff**

- **M1.** `share-state.ts:58-75`: the zip-bomb cap is checked only after fflate has inflated everything. `Inflate.push(data, true)` inflates the whole input into one buffer before `ondata` runs.
  - Probe: a 15,631-character fragment inflates the full 12 MB, then gets rejected (57 ms).
  - The real bound is about 12 MB because of the 16,000-character cap, so this is harmless, but the "streaming cap" claim is not true.
  - Fix: push the compressed bytes in slices of about 1 KB.
- **M2.** `share-state.ts:93`: decoded state is a raw `JSON.parse` result. Own `__proto__` keys are safe until a tool's `parse` uses `Object.assign` or `merge`. Defence in depth: use a reviver that drops `__proto__`, `constructor` and `prototype` keys.
- **M3.** `use-shareable-state.ts:117`: when the fragment is over its limit, `size` is a character count, so the tooltip shows "Too large to share as a link (6 KB)", which looks small. Report the JSON size, or word it "6,000 characters".
- **M4.** `use-shareable-state.ts:89`: `JSON.stringify(select())` runs on every render. For Text Diff with large inputs this costs time on every keystroke. Memoise on the tool's own inputs, or debounce.
- **M5.** `handoff.ts:52`: `text.length` counts UTF-16 code units, but the message says "50 MB". Count bytes, or word it as characters.

**Crypto**

- **M6.** `aead.ts:70-80`: `seal` accepts `pbkdf2` with 1 iteration and Argon2id with 8 KiB. Enforce a floor on the encrypt side (for example PBKDF2 at 100,000 or more, Argon2id m at 19 MiB or more per OWASP), with a test-only escape hatch. `open` must keep accepting whatever older versions wrote.
- **M7.** `aead.test.ts`: there is no frozen known-answer envelope. Users keep `.enc` files, so add one fixed sealed hex vector (PBKDF2 at 1,000 iterations) that must keep opening. This guards the header layout and the NFC handling.
  - The "header byte is AAD" case flips a salt byte, which changes the derived key anyway, so it does not prove the AAD binding. It would only be provable with a non-KDF header byte, and none exists beyond magic, version and id, which are checked first. Fix the comment.
- **M8.** `digest.ts:255` and `:263`: `CRYPTO[id]` and `CHECKSUMS[id]` are plain-object lookups. An id such as `toString` from untrusted settings or share state gives a TypeError instead of `INVALID_INPUT`. Use `Object.hasOwn` or a `Map`.
- **M9.** `killable-client.ts:54-58` with `text-client.ts:36-38`: aborting a call on the shared `textWorker()` terminates the shared worker. That cancels every other tool's in-flight job, against the intent of spec §4.4. Either make the singleton a plain RPC client (abort message only, no terminate) or document that callers must not pass signals to it.

**Encoding**

- **M10.** `encoding.ts` `bytesToBinary` (end of file): `groupBy <= 0` loops forever (`i += 0`). Validate that `groupBy` is 1 or more.
- **M11.** `encoding.ts` `base58ToBytes`: `input.trim()` shifts error positions when there is leading whitespace.
- **M12.** `encoding.ts` `base32ToBytes`: non-zero trailing bits and wrong padding counts (`MY=`) are accepted. That is fine for a lenient decoder; note it in the doc comment, or add `strict`.

**Time**

- **M13.** `time/zones.ts:68-71`: offsets are rounded to whole minutes. LMT offsets with seconds therefore make every historic wall clock `skipped` and 21 s off.
  - Probe: Europe/Dublin 1900-01-01 12:00 gives `status: 'skipped'`.
  - Fix: compare in milliseconds inside `wallClockToEpoch`, and round only for display.
- **M14.** `time/format.ts:91-109` and `time/parse.ts:183` and `:211`: `Date.UTC(y, …)` maps years 0-99 to 1900-1999, so `isoWeek`, `dayOfYear` and relative day shifts are wrong for those years. Use `setUTCFullYear`, as `utcOf` already does.
- **M15.** `time/parse.ts:56-79`: ISO offset hours and minutes are not range-checked (`+99:99` is accepted).

**Data formats**

- **M16.** `xml.ts:85-156` and `:273-301`: `exact`, `write` and `convert` are recursive. Firefox's expat has no depth limit, so very deep XML can overflow the stack. Make them iterative, or catch `RangeError` and map it to `INVALID_INPUT`.
- **M17.** `xml.ts:101-109`: the DOCTYPE internal subset (`[ <!ENTITY …> ]`) is dropped by `prettyXml`. `prettyXml(Document)` also loses the XML declaration.
- **M18.** `xlsx-write.ts:11-17`: lone surrogates and U+FFFE/U+FFFF pass the filter, but XML 1.0 forbids them and Excel then refuses the file. There is no check for the 16,384-column limit.
- **M19.** `ndjson.ts` has no test file. The plan says "tests per file".

**Settings, commands, syntax and licences**

- **M20.** `tool-settings.ts:62-71`: `sanitize` checks only the top-level JSON kind. Array elements and nested object shapes from storage are trusted, so for example `history: string[]` can come back holding objects.
- **M21.** `tool-commands.ts:17-20`: `Ctrl+Alt` combos are allowed in fields. On Windows, AltGr is reported as Ctrl+Alt, so a `Mod+Alt+Q` style shortcut fires while a German user types `@`. Avoid Ctrl+Alt combos in tool command defaults, or exclude `e.getModifierState('AltGraph')`.
- **M22.** `syntax/languages/js.ts:121-128`: after the keyword `this`, `/` is taken as the start of a regex (cosmetic misclassification).
- **M23.** `src/app/licences.ts`: `fflate` (MIT), which A1 now uses for share and XLSX, and other already-bundled packages are not listed. The file is also not used anywhere yet. Add `fflate` now, and note in the plan which Part renders the list.
